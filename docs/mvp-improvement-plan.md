# План семи доработок MVP FlowStaff AI

Каждый этап выполняется отдельно: реализация → проверка критериев → фиксация результатов → коммит → следующий этап. Данные для приёмки создаются только в изолированном окружении. Существующие пользовательские возможности и права сохраняются.

| Этап | Результат | Критерии приёмки | Состояние |
| --- | --- | --- | --- |
| 1. Администрирование ML | Интерфейс кандидатов и метрик V2; обучение, импорт и ручная активация через Java; аудит | ADMIN имеет доступ; остальные роли и POST без CSRF отклоняются; отклонённый кандидат не активируется; рабочий прогноз сохраняется | Принят |
| 2. Полнота признаков | Неизвестная нагрузка передаётся как null; доступны счётчики дней и неизменяемые дневные наблюдения | Ноль отличается от пропуска; повторный сбор не меняет прошлое; старые контракты читаются; тесты расчёта | Принят |
| 3. Кадровые события | Категории увольнений, идемпотентная доставка и ежедневный сбор/разметка | Создание/исправление/отмена кадрового события доходят до ML; недоступность сервиса не теряет событие; старые метки пересматриваются адресно | В работе |
| 4. Оценка качества | Временной бэктест, калибровка без утечки и отчёт качества | Группы и даты разделены; мало данных даёт понятный отказ; метрики и происхождение данных видны; реальное качество не выдаётся за проверенное на синтетике | Ожидает |
| 5. Единый ML-цикл | Старые вызовы обучения совместимы с единым управляемым циклом; защита публикации и откат | Конкурентное обучение/активация контролируются; отказ не заменяет активную модель; прежние прогнозы и API работают | Ожидает |
| 6. Воспроизводимая приёмка | Единый сценарий проверок, задачи/Kanban, отказ workload и восстановление | Запуск на отдельном стенде; проверяемые результаты и ненулевой exit code при ошибке; восстановление в отдельные тома | Ожидает |
| 7. Интерфейс | Согласованная сетка KPI и сворачиваемые мобильные фильтры | 1440×900, 1280×720, 390×844; клавиатура, aria, сохранение фильтрации; без горизонтального переполнения и ошибок JS | Ожидает |

Реальная прогностическая пригодность подтверждается только на достаточной кадровой истории. Реализация инструментов оценки не подменяет отсутствующие данные.

## Журнал выполнения

Результаты проверок и номера коммитов добавляются после каждого этапа.

### Этап 1 — принят

8 целевых Java-тестов, реальное обучение и активация через Java, доступ ADMIN/запрет EMPLOYEE и PROJECT_MANAGER, CSRF, 404 для отсутствующей версии и CSV-шаблон — успешно. Браузер: 1440×900, 1280×720, 390×844, без переполнения и JS-ошибок, фокус доступен. Логи: `output/improvement-stage1-*`. Подготовлен быстрый изолированный стенд из локальных JAR. Коммит 20.

### Этап 2 — принят

105 Java-тестов полного набора и 6 целевых тестов после уточнений; 58 ML-тестов и дополнительный тест заморозки снимка — успешно. HTTP-проверка на MySQL подтвердила null/ноль, счётчики, сохранение первого наблюдения, исключение прошлых/будущих проекций и рабочий прогноз Java. Логи: output/improvement-stage2-*. Коммит 21.
