# Этап 9. Обучение ML-модели

Этап реализует воспроизводимое обучение первой объяснимой модели прогнозирования текучести и хранение её версий.

## Конвейер обучения

- используются только снимки с заполненным `target_label`;
- требуется не менее 10 строк и минимум по два примера классов 0 и 1;
- числовые пропуски заполняются медианой обучающей выборки;
- категориальные признаки обрабатываются `OneHotEncoder(handle_unknown='ignore')`;
- числовые признаки масштабируются `StandardScaler`;
- базовый алгоритм — `LogisticRegression` с `random_state=42`;
- сначала применяется временное разделение по `snapshot_date`; если тестовая часть не содержит оба класса, используется воспроизводимое стратифицированное разделение;
- сохраняются ROC-AUC, F1, Recall, Precision и Accuracy.

## Model Registry

Миграция `ml-004-model-training-registry` добавляет таблицы `ml_model_versions` и `ml_training_runs`. Для каждой версии сохраняются алгоритм, дата обучения, хеш схемы признаков, хеш датасета, состав признаков, метрики и размеры train/test.

Артефакт записывается атомарно в каталог `MODEL_STORAGE_PATH`. Новая версия активируется только после успешного сохранения артефакта и записи в реестр. При загрузке проверяются version и hash схемы. Запрос обучения содержит idempotency key и не повторяется автоматически.

## API и интерфейс

- `POST /internal/v1/train` и `GET /internal/v1/model/info` во внутреннем ML-сервисе;
- `POST /api/v1/ml/train` и `GET /api/v1/ml/model` через Enterprise Application;
- endpoints и экран `/admin/ml` доступны только роли `ADMIN`;
- экран показывает реальное число размеченных строк, активную версию, алгоритм, дату, пять метрик, признаки и контрольные хеши;
- успешные и неуспешные запуски обучения фиксируются в аудите без исходных строк датасета.

Прогнозирование и объяснение факторов относятся к этапу 10.

## Проверка

- pytest проверяет одинаковые метрики и вероятности при повторном обучении с `random_state=42`;
- pytest сохраняет артефакт и загружает его заново с проверкой версии и схемы;
- MVC-тесты проверяют запуск обучения, выдачу информации о модели и ограничение доступа.

Результат приёмки: 25 pytest и 3 целевых MVC-теста прошли. Образы пересобраны,
`enterprise-app`, `attrition-ml-service`, `workload-service` и MySQL запущены с состоянием
`healthy`; миграция `ml-004-model-training-registry` применена. В браузере проверены вход ADMIN,
экран и API модели, пустое состояние при отсутствии обучающей выборки, блокировка запуска,
отсутствие горизонтального переполнения и режим reduced motion на размерах 1440×900,
1280×720 и 390×844.

В локальной базе при приёмке не было размеченных строк, поэтому интерфейс и API корректно
показывали `NOT_TRAINED`. Создание, повторяемость и загрузка versioned artifact покрыты
автоматическими тестами без добавления демонстрационных данных в рабочую базу.
