# Этап 11. Интеграция Enterprise ↔ ML

Enterprise Application использует Attrition ML Service через адаптер
`AttritionPredictionGateway`; Java-приложение не загружает joblib-артефакт и не выполняет
inference самостоятельно.

## Интеграция

- для ML-клиента настроены connect/read timeout;
- ограниченный retry с backoff применяется только к идемпотентным predict, batch predict и model-info;
- train, импорт датасета и сохранение feature snapshots автоматически не повторяются;
- массовый пересчёт делит данные на настраиваемые пакеты и не выполняет N одиночных ML-вызовов;
- ошибки одной строки batch не отменяют сохранение корректных прогнозов;
- при недоступности ML ранее сохранённый одиночный прогноз возвращается со статусом
  `STALE_FALLBACK`, а без сохранённого результата выдаётся контролируемая ошибка
  `ML_SERVICE_UNAVAILABLE`.

## Хранение

Миграция `core-008` создаёт:

- `attrition_predictions` — сотрудник, дата признаков, время расчёта, горизонт 90 дней,
  вероятность, риск, `model_version_id` и строковая версия модели;
- `attrition_prediction_factors` — до пяти факторов, вклад, направление и пользовательский текст.

Повторный расчёт сотрудника за ту же дату той же версией модели обновляет запись и факторы,
не создавая случайный дубликат. Частичный или полный сбой batch не удаляет прежние прогнозы.

## Внешний API

- `GET /api/v1/attrition/employees/{employeeId}` — последний сохранённый прогноз;
- `POST /api/v1/attrition/employees/{employeeId}/recalculate` — одиночный пересчёт;
- `POST /api/v1/attrition/recalculate` — пакетный пересчёт активных сотрудников.

Индивидуальные операции доступны ADMIN, ENTERPRISE_MANAGER и DEPARTMENT_MANAGER с проверкой
области подразделения. Массовый пересчёт доступен только ADMIN и ENTERPRISE_MANAGER.

- 35 тестов `pytest` прошли успешно;
- полный Maven-прогон: 81 тест, без ошибок и пропусков;
- Docker-образы собраны, Enterprise, Attrition ML, Workload и MySQL находятся в состоянии healthy;
- Liquibase применил `core-008` и `ml-005-attrition-risk-thresholds`;
- smoke-запрос inference без обученной модели вернул контролируемый `409 MODEL_NOT_TRAINED`.

Интерфейс в этих этапах не изменялся, поэтому отдельная браузерная проверка экранов не требовалась.
