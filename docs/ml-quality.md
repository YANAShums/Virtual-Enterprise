# Оценка модели текучести

Оценки модели не являются подтверждением пригодности для кадровых решений. В интерфейсе показывается `NOT_VALIDATED`, пока нет проверенной реальной истории и согласованных с HR порогов. `REAL_HISTORY` в CSV — заявление источника, а не автоматическое доказательство достоверности.

При обучении сотрудники разделяются на независимые группы для подбора модели, калибровки вероятностей и финальной проверки. Sigmoid-калибратор обучается без балансировки классов на отдельной группе. Проверочная группа не используется для подбора или калибровки; при сравнении новых версий сохраняется контрольная группа действующей модели. После многократного выбора версий по одной группе потребуется свежая внешняя проверка.

В карточке и JSON метрик доступны Brier до и после калибровки, интервалы вероятности с наблюдаемой долей уходов, precision/recall при охвате 10% сотрудников. Улучшение Brier не обещается: отчёт показывает фактическое значение. Для sigmoid-калибровки нужна положительная связь сигнала на независимых сотрудниках; иначе обучение отклоняется.

Временной бэктест использует более поздние даты. Из обучения исключаются сотрудники теста; окно метки каждого обучающего примера должно закончиться до первой тестовой даты. Отдельно выводятся метрики подразделений при наличии не менее 30 строк и обоих классов. При короткой истории или отсутствии независимых когорт возвращается `INSUFFICIENT_DATA` с причиной. Это не ошибка работоспособности сервиса.

Необязательный столбец CSV `data_origin`: `REAL_HISTORY`, `SYNTHETIC`, `UNKNOWN` (по умолчанию). Старые строки получают `UNKNOWN`; демонстрационный генератор явно пишет `SYNTHETIC`. Состав данных сохраняется в неизменяемом архиве набора и отчёте модели. В API метрик не публикуются списки сотрудников, использованных для калибровки.

Для реальной приёмки: собрать исторические снимки без постфактум исправленных признаков, проверить категории увольнений и полноту наблюдения, выделить независимый поздний период, согласовать допустимое число сигналов с HR и проверить ошибки по подразделениям. Текущие границы риска 0,30/0,60/0,80 сохранены; подбирать их без реальных данных нельзя.
