# Системный редизайн FlowStaffAI

## Карта до изменений

Аудит 30 октября 2026: React 19 + TypeScript + Vite, React Router, TanStack Query, Radix Dialog и Phosphor. Tailwind, Bootstrap runtime и отдельные layout по ролям отсутствуют.

| Уровень | Реализация |
|---|---|
| Shared layout | App в frontend/src/main.tsx: sidebar, topbar, поиск задач, аккаунт, мобильный Radix navigation |
| Shared components | ui.tsx: Button, Panel, Empty, StatusBadge; renderer.tsx: Render, PageUI, вкладки, статус задачи, drawer, подтверждение |
| Design tokens | tokens.css: цвета, шрифты, размеры, motion; styles.css: компоновка серверных контрактов; product-theme.css: единый визуальный слой |
| Самостоятельные экраны | Overview, Projects, People, Login, TaskCreate, dev DesignSystem |
| Остальные экраны | PageContent → Render, по внутренним ui-contracts; бизнес-логика и права остаются на сервере |

## Маршруты

- /login, /dashboard.
- /projects, /projects/new, /projects/{id}, /projects/{id}/edit.
- /tasks, /tasks/{id}, /tasks/{id}/edit, /kanban; создание — drawer /kanban?create=1.
- /employees, /employees/new, /employees/{id}, /employees/{id}/edit.
- Профиль: обзор, задачи, график, отсутствия, навыки, текучесть, кадровая история; /employees/{id}/absences/new, /absences/{id}/edit, /skills/new, /skills/{id}/edit.
- /workload, /attrition, /reports, /notifications.
- /admin и section: departments, positions, schedules, users, roles, calendar; формы new/edit/delete справочников и пользователей; /admin/settings/edit.
- /admin/ml, /admin/ml/models.
- /dev/design-system — только Vite DEV.

## Роли и ограничения

Реальные роли: ADMIN, ENTERPRISE_MANAGER, DEPARTMENT_MANAGER, PROJECT_MANAGER, EMPLOYEE, OBSERVER. HR как отдельная роль не существует. Кадровые прогнозы и отчёты разрешены ADMIN, ENTERPRISE_MANAGER, DEPARTMENT_MANAGER. Справочники/управление — ADMIN. PROJECT_MANAGER управляет проектной работой в своей области ответственности. EMPLOYEE меняет доступные собственные задачи. OBSERVER — чтение согласно серверной области доступа. Не добавлять фиктивные права ради совпадения с брифом.

## Найденные визуальные пробелы

- Info использовал яркий синий вместо Dust Blue. Нейтральные графики и прогресс серые.
- KPI одинаковые, нет контекстных акцентов.
- Рабочее пространство почти белое; фильтры, вторичные блоки и карточки недостаточно разделены.
- Пустые состояния без иконки/перехода; loading — одиночная плашка вместо skeleton.
- В профиле подпись графика всё ещё называла бирюзовый и оранжевый цвет.
- Donut получал прежние цвета из серверного style. Отображение нужно перевести на токены без изменения величин.
- Dev UI kit не покрывал drawer/dropdown/loading полностью.

## План

1. Foundation: Graphite × Lime × Lilac × Dust Blue; сохранить согласованные шрифты Suisse / Onest / JetBrains Mono.
2. Shared primitives и состояния: KPI, AIInsight, Empty, Alert, Skeleton; единые формы, таблицы, статусы, drawer.
3. Распространить оформление на все существующие маршруты, включая системные страницы и кадровые вкладки.
4. Расширить /dev/design-system настоящими интерактивными компонентами.
5. Одна пакетная проверка маршрутов/ролей/разрешений/доступности/адаптивности, исправление найденных дефектов и подтверждение.

Рабочий график показывает только реальные плановые данные, без вымышленного AI-прогноза. Модель, горизонт и время расчёта показываются только при наличии источника. Исходные backend/PDF изменения пользователя остаются вне коммита оформления.

## Реализованные изменения

- В tokens.css введены Dust Blue, текстовый и мягкий варианты, второй уровень фона, размеры текста/контролов. Сохранены утверждённые Graphite, Lime, Lilac и семантические цвета.
- В ui.tsx добавлены переиспользуемые IconButton, Input, KPI, AIInsight, Alert, Skeleton. Empty получил иконку, объяснение, контекст и переход.
- Sidebar общий для всех ролей: elevated active, узкий lime-индикатор, секции 11 px. Дополнительных тем по ролям нет.
- Overview использует контекстные KPI: сотрудники lilac-soft, задачи Dust Blue, проекты graphite, загрузка lime-soft. AI empty компактный; без фиктивного названия модели.
- Обычный график и прогресс используют Dust Blue; текущая точка — lime. На телефоне график прокручивается внутри панели, подписи не уменьшаются до нечитаемого размера.
- Список проектов, карточки проектов, задачи, доска, master-detail сотрудников, кадровые вкладки, загрузка, прогнозы, отчёты, настройки, справочники и ML-страницы используют общие поверхности и состояния.
- Heatmap сохраняет серверные уровни, выделяет текущую дату и выбранную ячейку. Подпись доступного имени включает сотрудника и статус, а не только процент.
- В профиле исправлена старая цветовая легенда. Donut сохраняет рассчитанные сервером доли, но отображает их цветами токенов вместо прежних бирюзовых значений.
- В рендерере добавлены настоящие Phosphor-иконки для empty/info/аналитики. Ответы сервера по-прежнему не исполняются как HTML/скрипты.
- В UI Kit добавлены dropdown, drawer, состояния загрузки, KPI-варианты, общие AI/info alerts, выбранная heatmap-ячейка и интерактивная демонстрация переноса.

## Методика и инструменты

Прочитаны инструкции Frontend UI Engineering, Redesign Existing Projects, Impeccable/craft floor/colorize, Product Design, Superdesign, UI/UX dashboard/design system/component/layout/motion/accessibility, Designly Typography/Composition, Visualize Data и Playwright. Приоритет имеют утверждённый бриф, доступность и существующая архитектура.

Загрузчик Impeccable недоступен из-за ограничения записи кэша; Superdesign CLI — из-за недоступности npm. Внешний canvas не создавался, авторизация не запрашивалась. Анализ и реализация выполнены локально. Браузерная проверка использует реальный Chromium и текущий backend; рабочие ответы не подменяются макетами.

- UI Kit: dropdown → toast, modal, drawer, Escape проверены. Все демонстрационные значения остаются только в dev-странице.
- Контейнер enterprise-app обновлён без пересоздания БД/volumes и остальных сервисов, состояние healthy. Dev UI Kit доступен на 127.0.0.1:5173/dev/design-system.
