# FlowStaff AI — этап 4: проекты, задачи и Kanban

Источник: FlowStaff_AI_Техническое_задание_v2.1.docx, этап 4. Реализация использует существующие доменные модели, API переходов статусов и общий AppShell.

## Реализованные функции

- Создание и редактирование проекта: код, название, описание, руководитель, даты, плановые часы, приоритет, статус, риск и готовность.
- Управление командой проекта. Руководитель включается автоматически, удалённые участники получают дату выхода, поэтому история состава не теряется.
- Проверка дат проекта, активных сотрудников и optimistic locking.
- Редактирование задачи: название, описание, исполнитель из команды проекта, приоритет, сроки и оценка.
- Переходы статусов через карточку и Kanban с проверкой допустимого маршрута, версии и обязательного комментария для возврата или отмены.
- Фильтры списка задач и доски по проекту, статусу, приоритету, поиску и просрочке.
- Комментарии задачи и чек-лист с созданием, переключением выполнения и удалением пунктов.
- Серверная проверка ролей; сотрудник может менять выполнение только своей задачи.
- Аудит изменений проекта, задачи, статуса, комментариев и чек-листа. Для основных изменений формируются outbox-события.

Карточки проекта и задачи показывают реальные данные. Для комментариев и чек-листов без записей используются пустые состояния.

## Миграция

`006-project-task-collaboration.sql` добавляет дату выхода участника проекта, комментарии и пункты чек-листа. После запуска Liquibase в рабочей базе зарегистрировано 6 changesets.

## Проверка

В общей приёмке этапов 3–4 выполнены 48 Java-тестов без ошибок. Покрыты изменение состава проекта, валидация дат, допустимые и запрещённые переходы задачи, устаревшая версия, API-ответы, валидация JSON и CSRF.

Ручной сценарий Playwright прошёл от входа ADMIN до проекта, задачи и Kanban. Задача переведена из «Запланировано» в «В работе», счётчики и live-status обновились, затем задача возвращена в исходный статус с обязательной причиной. В MySQL подтверждены две записи `TASK_STATUS_CHANGED`; серверные логи и браузерная консоль без ошибок. Проверены размеры 1440×900, 1280×720 и 390×844.

Снимки проверки находятся в игнорируемой папке `output/playwright/`.
