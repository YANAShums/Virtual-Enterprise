# Управление моделями MVP

Единая страница: `/admin/ml/models` (ADMIN). Старый адрес `/admin/ml` перенаправляется сюда. Прежние API импорта, информации о модели и прогнозов сохраняются. Старый запрос обучения `/api/v1/ml/train` создаёт кандидата в общем V2-цикле; автоматическая активация больше не выполняется. Поле `status` возвращает `CANDIDATE` или `REJECTED`. После проверки требуется ручная активация на странице моделей.

Исторические V1-импорты копируются в V2 перед обучением, если окно метки закончено. Исходные таблицы остаются для совместимости; уже существующие V2-снимки не перезаписываются. Неизвестные счётчики нагрузки остаются пропусками. Старый код расчёта артефактов оставлен для чтения существующих версий и регрессионных тестов; HTTP-обучение использует единый цикл.

Обучение и активация защищены общей блокировкой MySQL `flowstaff-ml-lifecycle`. Владеющее соединение сохраняется до завершения операции, включая коммиты сессии. Занятый ресурс возвращает HTTP 409. Повтор V1-запроса с тем же `idempotencyKey` возвращает исходного кандидата; после неуспешной попытки нужно создать новый ключ. В MVP используется один ML-процесс; отдельная очередь обучения не требуется.

До публикации проверяются гейт качества, наличие и SHA-256 исходного артефакта. Обновления старого и нового реестров выполняются в одной транзакции одной ML-базы. Файл для старого сервинга публикуется атомарным переименованием. При отказе активная запись не заменяется. Неиспользуемый файл после аварии может остаться на диске; он не выбирается реестром автоматически.

Для возврата версии: открыть страницу моделей, выбрать предыдущую одобренную архивную версию и нажать «Активировать эту версию». Проверить `/api/v1/ml/model`, затем выполнить контрольный прогноз. Повторная активация не переобучает модель; исторические прогнозы сохраняют исходную версию. При потере всех артефактов восстановить базу и каталог моделей из согласованной резервной копии, а не изменять флаг ACTIVE вручную.
