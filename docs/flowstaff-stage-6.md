# Этап 6. Интеллектуальный подбор исполнителя

При создании задачи можно указать требуемые навыки. Система сопоставляет их с активными навыками сотрудников, рассчитывает текущую и прогнозную загрузку и сортирует доступных участников проекта по итоговому рейтингу.

Рейтинг имеет прозрачную формулу из ТЗ:

- 40% — прогнозная загрузка;
- 25% — совпадение навыков;
- 15% — доступность в выбранные даты;
- 10% — участие в проекте;
- 10% — количество активных задач.

Для каждого кандидата интерфейс показывает рейтинг, загрузку «сейчас → после», статус и от двух до четырёх причин. Первый доступный кандидат помечается как рекомендуемый. При загрузке 100–120% показывается предупреждение, свыше 120% требуется отдельное подтверждение и причина.

Добавлены API `GET /api/v1/tasks/{id}/recommendations` и `POST /api/v1/tasks/{id}/reassign`. Переназначение повторно проверяет версию задачи и идентификатор расчёта, сохраняет историю назначения и подтверждение критической перегрузки. Требуемые навыки задачи хранятся в `task_required_skills`.

Общая приёмка этапов 5 и 6 включает модульные тесты расчётов, миграции обеих баз, API и браузерную проверку экранов загрузки и создания задачи на desktop, compact и mobile.


## Результат совместной приёмки

- Maven: 62 теста, ошибок и пропусков нет.
- Liquibase: применены workload-002 и core-007; оба сервиса имеют статус healthy.
- Хранилище: после открытия экрана сформированы 42 дневных и 6 периодических снимков.
- Browser QA: /workload и /kanban проверены на 1440×900, 1280×720 и 390×844; ответы 200, переполнения страницы и ошибок консоли нет.
- API загрузки и рекомендаций возвращают 200. Кандидаты отсортированы по рейтингу; причины, предупреждение и подтверждение критической перегрузки отображаются корректно.
- В текущей базе нет заведённых навыков, поэтому интерфейс показывает честное пустое состояние; расчёт совпадения навыков покрыт модульными тестами и включается после добавления реальных навыков.
