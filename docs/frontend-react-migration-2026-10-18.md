# Перевод интерфейса FlowStaff на React

Дата: 18 октября 2026.

## Реализовано

Интерфейс переведён на React 19.3.1 и TypeScript. Сборка — Vite, маршрутизация — React Router, загрузка и обновление данных — TanStack Query, диалоги — Radix. Локальный Onest сохранён, прежние библиотеки иконок заменены небольшим набором Phosphor. Навигация преимущественно текстовая.

Старые CSS, Bootstrap, Lucide и браузерные скрипты удалены. Добавлено графитовое оформление с коралловым акцентом: обзор команды, карточки проектов, списки задач и сотрудников, Kanban, профили, формы, аналитика, отчёты и администрирование. Вход оформлен в том же стиле. Фильтры и подробности раскрываются по необходимости; вымышленные показатели не добавлены.

Перенесены поиск, вкладки с клавиатурным управлением, мобильная навигация, быстрый просмотр сотрудника, дневная детализация загрузки, комментарии, чек-лист, экспорт и операции форм. Создание задачи использует реальный расчёт загрузки. Изменение параметров аннулирует предыдущий расчёт, критическая перегрузка требует подтверждения и причины. Переходы статусов сохраняют версию записи и обязательные комментарии. Перетаскивание имеет альтернативу через меню статуса.

React включается в готовый Spring Boot JAR. Maven собирает frontend, Docker использует отдельный Node-этап и кеш Maven, CI устанавливает Node.js 22. Для запуска готового приложения Node.js не нужен. Основной проект запущен на http://localhost:8080/dashboard.

## Граница изменений

Бизнес-сервисы, роли, права, JSON API и пороги нагрузки/риска не переписаны. Сохраняются Spring Session, CSRF, оптимистическая блокировка и серверная валидация.

Thymeleaf оставлен **как внутренний контракт чтения и форм** в `enterprise-app/src/main/resources/ui-contracts`. React запрашивает его с заголовком `X-FlowStaff-View: 1`, разбирает поля, значения, ошибки, ссылки и разрешённые действия и создаёт React-элементы. Скрипты и inline-обработчики не выполняются, `dangerouslySetInnerHTML` не используется. Обычная браузерная навигация получает React shell. Экспорт, POST-операции и API проходят в существующие контроллеры.

Это полная замена пользовательского оформления и браузерного поведения, но не перевод всего backend на отдельный JSON REST API. Такой адаптер выбран для сохранения существующих операций MVP. Новые самостоятельные экраны следует подключать к явным JSON DTO; постепенная замена адаптера позволит позднее отделить frontend без повторной переделки дизайна.

## Проверки

| Проверка | Результат |
|---|---|
| Общая Java-проверка | 111 тестов, ошибок нет; включены 4 новых теста выдачи React shell и сохранения MVC/API/экспорта |
| TypeScript и production-сборка | Успешно |
| Полная Docker-сборка | Успешно |
| 28 маршрутов × 3 размера | 84 проверки при 1440×900, 1280×720, 390×844; переполнений и ошибок JavaScript нет |
| Мобильное меню | Escape и возврат фокуса проверены |
| Рабочие операции | 15 сценариев прошли на изолированном стенде |
| Область перетаскивания | Дополнительно проверен сброс карточки в пустое место всей колонки |
| Основное окружение 8080 | 10 разделов открываются; приложение, MySQL, workload и ML healthy |

Рабочие сценарии включают неверный и успешный вход, подтверждение критической перегрузки и сброс расчёта, создание задачи, прямой и обратный переход статуса, перетаскивание карточки, чек-лист и комментарий, вкладки сотрудника, детализацию загрузки, CSV/XLSX, создание и редактирование проекта и сотрудника, справочник, серверную ошибку с сохранением значений, выход и повторный вход, ограничения сотрудника на сервере.

В ходе проверки исправлены упаковка ресурсов в JAR, перенаправления Vite, передача значения кнопки экспорта, повторная загрузка формы после выхода, переполнение мобильных таблиц и длинного заголовка, возврат фокуса и обработка перетаскивания.

Сценарии создания записей выполнялись на отдельном стенде 18080. Основное окружение проверялось входом и чтением. Проверки проведены в Chromium; Safari и Firefox отдельно не проверялись. Обучение и качество ML этой работой не оценивались.
