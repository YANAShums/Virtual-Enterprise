# FlowStaff AI — этап 2: администрирование организации

Источник: FlowStaff_AI_Техническое_задание_v2.1.docx, этап 2 и требования FR-AUTH-004/005,
FR-ORG-001–005. Реализация сохраняет Spring Boot 3.5.3, Thymeleaf, MySQL и Liquibase.

## Доступные функции

Войти как ADMIN и открыть `/admin`.

| Раздел | Операции и ограничения |
|---|---|
| Подразделения | Создание, изменение, родитель, руководитель, архивирование и удаление свободной записи. Циклы запрещены; связанные подразделения и сотрудники защищены от удаления |
| Должности | Код, название, грейд, описание, активность. Архивные записи исключены из новых назначений; использованные должности можно архивировать |
| Пользователи | Создание, изменение логина/email, роли, связь с сотрудником, блокировка/разблокировка, сброс пароля, архивирование |
| Роли | Просмотр системных ролей и назначение набора ролей пользователю. Коды ролей фиксированы, поскольку используются серверными проверками доступа |
| Графики | Семь дней недели, 0–24 часа в день, часовой пояс, автоматическая недельная сумма, активность. Использованные графики защищены от удаления |
| Календарь | Рабочие, сокращённые, праздничные и выходные дни; уникальная дата, описание и доступные часы. Исключения участвуют в расчёте нагрузки |
| Предприятие | Редактирование кода, названия и часового пояса |

Все административные изменения требуют ADMIN и CSRF. Роль проверяется также на сервисах.
Изменение пользователя увеличивает security_revision: прежняя сессия отклоняется на следующем
запросе, включая блокировку, смену ролей и сброс пароля. Учётные записи архивируются вместо
физического удаления для сохранения истории. Свою административную роль снять нельзя;
блокировка последнего действующего администратора запрещена.

Пароли хешируются BCrypt, не возвращаются в HTML формы. Новые пароли: минимум 10 символов,
максимум 72 байта UTF-8. Пустой пароль при редактировании сохраняет прежний хеш.
Сотрудник не может быть связан сразу с двумя учётными записями.

Формы передают version; устаревшие изменения отклоняются. Изменения иерархии и проверки
последнего администратора сериализуются блокировкой строки предприятия. Это соответствует
существующей архитектуре одного предприятия (id=1), а не добавляет мультитенантность.
Удаление требует отдельного подтверждения. Ошибки дубликатов и связей выводятся без SQL/stacktrace.

## Приёмка

- `mvn -B test`: 42 теста, 0 ошибок (9 Workload, 33 Enterprise).
- MVC-тесты: рендер всех новых форм, скрытие пароля, валидация часов, CSRF,
  запрет доступа пяти неадминистративным ролям.
- Тест фильтра: отзыв уже действующей сессии при изменении security_revision.
- `tools/verify-stage2.py`: реальный HTTP → Spring → MySQL, отдельная тестовая БД.
  Проверены CRUD, дубликаты, циклы, руководитель, устаревшие формы, связанные удаления,
  архивные назначения, блокировка/разблокировка, сброс пароля, роли, связь с сотрудником,
  архивирование пользователя и защита последнего администратора.
- Расчёт нагрузки через Workload проверен на созданном сотруднике: график 6 часов → 7 часов;
  праздник → 0 часов; сокращённый день → 4 часа; удаление исключения → 7 часов.
- Playwright: вход ADMIN, таблица подразделений, создание подразделения через форму,
  проверка формы графика на ширине 390 px. Снимки находятся в игнорируемом `.playwright-cli/`.
- Полный CRUD-прогон успешен 16.09.2026; браузерная проверка завершена 17.09.2026.

### Повторение интеграционного теста

Команды выполняются из корня проекта. Создаются отдельные контейнеры и тома, приложение на
localhost:18080 и MySQL на localhost:13307. Тест создаёт записи только в тестовой БД.

```powershell
docker compose -p flowstaff-stage2 -f docker-compose.yml -f tools/compose.stage2-test.yml up -d --build --wait --wait-timeout 180
$env:STAGE2_TEST_URL = 'http://localhost:18080'
python tools/verify-stage2.py
docker compose -p flowstaff-stage2 -f docker-compose.yml -f tools/compose.stage2-test.yml down
```

Тест рассчитан на исходные локальные учётные записи admin/admin123 и employee/employee123,
предприятие и проект из seed. Данные рабочих томов не затрагиваются; тестовые тома сохраняются.
Рабочее приложение обновлено 17.09.2026: core-003 применена, контрольные суммы прежних
миграций и количества сотрудников/проектов/задач сохранены. Повторная проверка основных
страниц, входа и работы при отключённом ML прошла. Временный стенд остановлен без удаления томов.

Логи выполненного прогона: `output/flowstaff/stage2-tests.log`, `stage2-integration.log`.

## Границы этапа

Кадровая история и полноценное редактирование сотрудников/отсутствий относятся к этапу 3.
Полный scope чтения данных руководителями и разрешения кадровых прогнозов остаются на последующих
этапах; назначение руководителя здесь сохраняет связь, но не заявляет завершение всей ролевой матрицы.
Произвольные коды ролей не создаются: права задаются шестью системными ролями ТЗ.
Справочники статусов/приоритетов/типов задач и пороги загрузки/ML-риска не входили в перечень
модулей этапа 2 и требуют дальнейшей реализации в соответствующих этапах задач и аналитики.
