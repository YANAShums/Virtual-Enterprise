# Этап 10. API прогнозирования и объяснения

Реализован Model Serving в `attrition-ml-service` без переноса Python-модели в Java-приложение.

## Возможности

- `POST /internal/v1/predict` рассчитывает прогноз для одного набора признаков;
- `POST /internal/v1/predict/batch` обрабатывает наборы признаков одним вызовом модели;
- ответ содержит probability, riskLevel, modelVersionId, modelVersion и до пяти topFactors;
- локальные вклады Logistic Regression агрегируются до исходных технических признаков;
- фактор содержит направление UP/DOWN и понятную пользовательскую формулировку;
- неизвестные категории обрабатываются сохранённым `OneHotEncoder(handle_unknown='ignore')`;
- некорректная строка batch возвращается в `errors`, не удаляя результаты корректных строк.

## Пороговые значения

Миграция `ml-005-attrition-risk-thresholds` создаёт настраиваемые уровни:

- LOW: `[0, 0.30)`;
- MEDIUM: `[0.30, 0.60)`;
- HIGH: `[0.60, 0.80)`;
- CRITICAL: `[0.80, 1]`.

Inference использует только активную версию из Model Registry и проверяет артефакт и схему.
Если модель не обучена или артефакт недоступен, API возвращает контролируемую ошибку.

Отдельная приёмка этапа не выполнялась: проверка объединена с этапом 11 и приведена в его отчёте.
