# Воспроизводимая приёмка MVP

Запуск из корня репозитория: `./tools/run-mvp-acceptance.ps1` (PowerShell 7, Java 21/Maven, Docker Compose с поддержкой `!override`, Python с `attrition-ml-service/requirements-dev.txt`). Скрипт использует локальную `.venv-ml`, если она есть. Отдельный ручной workflow `MVP acceptance (isolated)` запускает тот же сценарий в GitHub Actions.

Проверки создают демонстрационные данные **только** в Compose-проекте `flowstaff-ml-check` с портами 18080/18081/18082 и MySQL 13307. Обычный проект на 8080 и его тома не затрагиваются. Используются публичные значения `.env.example`. После первой сборки можно указать `-SkipBuild`; после уже выполненных unit-тестов — `-SkipUnitTests`. `-SkipRestore` отключает только дорогое восстановление, что нужно явно указать в результате приёмки.

Сценарий проверяет ML-контракты и гейт, администрирование и роли, пропуски/неизменяемую историю нагрузки, кадровые события при отказе ML, отчёт качества, блокировку и возврат модели, создание задач и переходы Kanban, устаревшую версию и ошибки ввода, административный CRUD, сохранённый прогноз во время отказа ML. При отказе workload проверяются 503, отсутствие создания задачи без расчёта, доступность страниц и восстановление расчёта после запуска сервиса. Любая неуспешная проверка останавливает сценарий с ненулевым кодом.

Восстановление выполняется отдельно в `flowstaff-restore-check` во временной MySQL на tmpfs. Перед копированием останавливаются пишущие сервисы **тестового** проекта для согласованного снимка трёх баз и файлов; они запускаются в `finally`. Проверяются SHA-256 комплекта и всех V2-артефактов, вложенные пути моделей, совпадение числа сотрудников, задач, кадровых событий, наблюдений, снимков, версий и прогнозов. После проверки временное окружение удаляется. Копии остаются в игнорируемом `output/ml-acceptance/backups`.

На рабочем развёртывании резервное копирование нескольких баз и файлов также нужно выполнять при остановленных записях или с отдельным механизмом согласования. Обычный периодический backup без такой остановки сам по себе не гарантирует межсервисный снимок одной секунды. Проверка restore здесь подтверждает целостность хранения; она не подменяет реальный бэктест ML и нагрузочную приёмку.

Результаты JSON и журналы сохраняются в `output`. Браузерные проверки расположены в `tools/browser-improvement-stage*.js`; они выполняются через Playwright CLI отдельно на 1440×900, 1280×720 и 390×844.
