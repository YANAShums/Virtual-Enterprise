## FlowStaff AI — этап 1 принят (16.09.2026)

Актуальное ТЗ: FlowStaff_AI_Техническое_задание_v2.1.docx.

- Все сервисы собраны и запущены; MySQL, Enterprise, Workload и ML имеют healthy.
- Bootstrap и Liquibase выполнены на пустом и повторно используемом томах; повторный запуск
  сохраняет checksums миграций и количества бизнес-записей.
- Исправлена повторная установка JDBC-драйвера в Liquibase-контейнере.
- Добавлены Java/FastAPI prod-профили с TLS, проверкой обязательных реквизитов и запретом demo-секретов.
- Dev-порты ограничены localhost, в TLS-профиле наружу доступен только Enterprise.
- Вход, cookie и расчёт Workload по HTTPS проверены на отдельном стенде с проверкой CA.
- При отключённом ML новый вход и все основные страницы работают. ML восстановлен.
- Java: 33 теста; Python: 16 тестов; проверки Compose и diff успешны.
- Предыдущий блокер Docker устранён: глобальный перезапуск WSL не потребовался.
- ML пока возвращает model=NOT_TRAINED. Обучение и прогнозы относятся к последующим этапам.

Подробная матрица: [этап 1](docs/flowstaff-stage-1.md).
Конфигурация и ограничения эксплуатации: [DEPLOYMENT.md](docs/DEPLOYMENT.md).
Этап 2 выполнен; следующий этап — сотрудники и кадровая история (этап 3).
Физическое разнесение узлов, полный RBAC/scope и автоматический backup/restore
не заявлены как выполненные; финальная эксплуатационная приёмка остаётся на этапе 14.

## Реализовано в архиве

- инфраструктура Maven multi-module;
- Docker Compose и автоматическая инициализация двух БД;
- Liquibase schema + seed;
- серверная авторизация и роли;
- основные JPA-сущности организации, сотрудников, проектов и задач;
- UI дашборда, сотрудников, проектов, Kanban и загруженности;
- создание задачи и проверка нагрузки;
- критическая перегрузка с подтверждением;
- переходы Kanban и optimistic locking;
- отдельный workload-service;
- аудит и outbox для операций с задачами;
- демонстрационные данные и учётные записи.

## Подготовлено архитектурно, но не реализовано полностью

- полное редактирование и административный CRUD сотрудников (создание из UI уже есть);
- полное редактирование и административный CRUD проектов (создание из UI уже есть);
- компетенции и взвешенный skill match из БД;
- комментарии, чек-листы и вложения;
- интерфейс регистрации отсутствий;
- внутренний центр уведомлений;
- генерация XLSX/PDF;
- настройка порогов загрузки и риска (назначение системных ролей уже реализовано);
- обработчик outbox с долговременными snapshot-таблицами.

Это осознанное ограничение первой демонстрационной сборки. Центральный пользовательский сценарий — распределение задач с оценкой загрузки — реализован.

## Упрощения безопасности MVP

- сервер проверяет роли на изменяющих операциях;
- сотрудник может менять статус только собственной задачи;
- полная иерархическая область доступа руководителя подразделения и проектная область для всех read-запросов оставлены для следующего этапа;
- демонстрационные списки доступны всем аутентифицированным пользователям.
